# inFAMOUS 粒子缺失与精确回读诊断（2026-10-08）

## 已确认的结论

火焰、浓烟主体缺失存在 CPU/GPU 数据一致性原因。同一程序、同一隔离存档、同样的测试步骤，
仅将 `BB_READBACKS=1`（Relaxed）切换为 `2`（Precise），车祸现场的火焰与浓烟主体重新出现。
这是实际画面的对照结果，不能把宽松模式中少绘制效果所得的帧率当作正确渲染性能。

目前不能断言所有粒子都异常。共用 GPU→CPU 反馈路径的效果有同类风险；纯 GPU 内部更新、
不依赖 CPU 回读的效果，以及使用其他材质或混合方式的火花、尘土等，需要分别验证。
当前存档的火焰/浓烟恢复，也不能代替获得烟气能力剧情和所有后续异能的验收。

## 证据与加载、渲染链路

1. 游戏资源由游戏自己的逻辑经 `src/runtime_file.c` 读取 `/app0` 文件，再生成 PS4 图形命令。
   引擎没有按“火焰文件名”单独加载粒子的实现。`art/cache/all_shaders.xpps` 是输入资源，
   转译的 SPIR-V、Vulkan 管线和集中缓存存于引擎输出目录。原始游戏资源没有改写。
2. 间接绘制参数的实际 GPU 回读发现，目标火焰绘制有 `732,1,0,0` 参数，即 183 个四边形。
   不能用旧的 CPU 内存副本判断 GPU 上的绘制数量为零。
3. 目标材质的 VS 为 `0xbbd2d927`、PS 为 `0x24dad4be`；使用 QuadList、透明混合和数组贴图。
   缓存中相关的八个 SPIR-V 模块通过 Vulkan 1.3 校验。数组贴图包含 BC3 512×512×16、
   256×256×64、128×128×256；“资源是数组”本身不能作为加载错误的证据。
4. 在隔离引擎缓存中临时用诊断色替代目标片元输出并去掉片元丢弃，能够看到粒子四边形。
   该实验结束后恢复原始转译模块并校验；诊断帧没有作为性能成绩。这证明几何生成和提交存在，
   但单独这一步不能区分贴图、透明度、丢弃条件或其输入参数错误。
5. 同程序精确/宽松回读对照最终进一步缩小原因：精确模式恢复火焰、浓烟主体，宽松模式再次缺失。
   精确模式会保护 GPU 修改的内存，CPU 读访问先获取最新 GPU 数据；宽松模式只在后续写入等路径
   处理一致性，纯 CPU 读取可能继续使用旧值。
6. 回读跟踪命中了真实游戏代码 `guest+0x3f3eff`，其指令为 `mov eax,[rax+4]`。
   读取地址包括 `0x106e259f04`、`0x106e282604` 等，来源为游戏 CPU 线程。
   可确定它读取 GPU 修改的 32 位反馈字段；缺少符号时不将该字段未经证明地命名为某个粒子计数器。

## 发现并修复的通用引擎缺陷

| 缺陷 | 修复 | 证据边界 |
|---|---|---|
| 间接绘制/派发参数未完整登记 Vulkan 间接读取依赖 | 登记 DrawIndirect 阶段与 IndirectCommandRead 访问，纳入后续写入冲突处理 | GPU 回归覆盖间接消费与参数复用；单独开启不足以恢复火焰 |
| GDS append/consume 翻译后的持久缓冲区缺少读写追踪 | 绑定、提交和后续复制均追踪真实写入 | 通用同步修复；未证明是主体缺失的唯一原因 |
| Windows 灵活内存区域分段后，右半段物理偏移没有更新 | 灵活内存与直接内存均推进物理偏移 | 新测试复现部分解除映射会清零错误区域，修复后通过 |
| 异步 CPU 上传读取受保护游戏页面，形成工作线程与 GPU 互等 | 已分类为 CPU 上传的数据从未保护的 backing 视图复制 | 精确模式从启动前卡住变为能进入实际场景；游戏自身读访问仍触发回读 |
| 纹理内容校验在缓存锁内读受保护页面，回读重新进入缓存锁 | 对 CPU 上传版本做分块 backing 校验，保留原 XXH3 校验值 | 符号化线程栈定位到 RefreshImage→xxhash→ReadMemory→HasImageOverlap；修复后原复现流程完整运行 |

CPU backing 校验只判断 CPU 上传数据变化。GPU 已修改的图像仍通过 `ObtainBufferForImage`
取得正确 GPU 版本；不能将 backing 通道用于绕过游戏的正常 GPU 回读。

## 实际游戏测量

以下均为当前车祸现场存档，预热 15 秒，静止和转镜头各测 10 秒。不是之前屋顶存档，不能跨场景直接比较。

| 实验 | 静止 FPS | 转镜头 FPS | 主体效果 | 说明 |
|---|---:|---:|---|---|
| 同程序 Relaxed | 37.82 | 53.15 | 火焰、浓烟缺失 | 正确性不合格 |
| 同程序 Precise，512 KiB 回读范围 | 20.13 | 23.33 | 火焰、浓烟出现 | 每帧约 7.4 次按需回读、约 20 ms 回读等待 |
| backing 校验修复后 Precise，4 KiB 回读范围 | 14.16 | 14.81 | 实际场景运行完成 | 每帧约 273～277 次按需回读、约 41 ms 等待；未采用 |

精确模式增加的 GPU 计算派发也有实际意义：静止场景约 1227 次/帧，对照宽松模式约 530 次/帧。
恢复正确效果后工作量改变，因此不能仅通过优化等待就保证回到缺失效果时的帧率。
F11 的分项存在嵌套、跨线程活动，时间不可直接相加。

对照报告：`out/runtime-benchmark/particle-{precise,relaxed}-fixed1.json`。
相同初始视角截图：`out/runtime-benchmark/particle-precise-fire.bmp` 与 `particle-relaxed-fire.bmp`。
新纹理校验复测：`particle-precise-hash-window4.json`。
隔离会话按既有规则只轮转保留最近两轮，用户原始会话没有清理。

## 验证与剩余工作

CPU backing 校验修复后，170 项 Python 测试、30 项原生单元测试、14 项真实 GPU 测试全部通过。
日志：`out/runtime-benchmark/particle-cpu-hash-tests-final.log`。
新增验证包含保护页面、内存分段与孔洞、64 KiB 校验分块边界，以及间接 GPU 参数消费。

2026-10-09 补充：合并已知回读窗口、扩大至 4096 KiB、绑定复用及按页校验的异步回读完成验证。
同一最终程序、预热缓存的同步/异步对照为：静止 21.64→25.39 FPS，转镜头 24.50→28.51 FPS。
扩大窗口但整窗版本作废的异步实验曾退化至 16.42/18.73，未作为默认；已改为只发布版本未变的页。
正常 CUSA00309 启动现默认精确回读及经过对照的优化设置，主体效果恢复优先于缺失效果时的高帧率。
新着色器正确性移植与完整记录见 `INFAMOUS_REFERENCE_COMPARISON.2026-10-08.zh-CN.md`。
用户将游戏移入 `game/CUSA00309` 后，所有 Windows 实际入口同步改为新路径。原始会话路径保留。
仍需优化精确回读和绘制前端开销，验证真实烟气剧情及其他粒子类别，未达到稳定 50–60 FPS。
用户长录制中的首次着色器编译慢帧、实体手柄震动和剧情完整播放，也不能仅凭上述粒子测试宣称全部解决。
