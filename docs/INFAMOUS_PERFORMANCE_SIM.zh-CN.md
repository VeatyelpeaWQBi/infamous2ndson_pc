# Windows 引擎组件性能模拟测试

## 运行

先关闭游戏及其他高负载程序。使用项目已安装的 Windows Python / MSYS2 CLANG64，不安装依赖。

```bat
build.bat --build-tests
performance-test.bat
```

默认读取最近一次 F11 正式 CSV 的最后一分钟，参考纹理集合访问计数确定合成操作数量。
只读输入，不恢复或删除录制，不启动游戏。没有 F11 时使用固定合成负载。
若现有诊断会话的游戏进程仍在运行，会拒绝执行基准，避免和游戏争用资源。

```bat
rem 只运行不需要显卡的哈希/缓存模型与注册变化校验
performance-test.bat --cpu-only

rem 固定工作量，便于跨版本比较
performance-test.bat --synthetic --operations 200000 --rounds 9 --seed 777

rem 和上一次相同负载/硬件的结果比较；读取后才轮换输出文件
performance-test.bat --compare out\performance-sim\latest.json

rem 自动化阶段验收：存在明确生产函数收益且其余生产场景无退化/无结论，才返回 0
performance-test.bat --require-gain
```

参数也支持 `--recording 路径` 指定现有 F11 文件。跨版本对比必须保持操作数、种子、覆盖范围和硬件一致。
数据路径、指纹、参数、程序指纹及结果一起保存在报告中。改变负载生成算法时应更新格式版本，不能混比。

退出码：0 表示正确性检查与所选执行完成；1 表示输入/程序/结果校验失败；
3 表示请求了 `--require-gain`，但没有达到阶段收益标准。仅退出码 0 不代表帧率提升。
没有可执行文件时明确失败，不隐式构建、安装或下载。

## 当前覆盖范围

| 场景 | 路径与目的 |
| --- | --- |
| texture_cache_small_set | 生产纹理哈希函数＋32,768 槽直接映射模型；512 个集合重复访问 |
| texture_cache_pressure | 同一函数和模型，50,000 个集合，检测碰撞和工作集压力；同时报告命中与查表耗时 |
| image_repeated_partial_read | 生产 Image::GetBarriers，连续只读包含 320 个子资源的视图 |
| image_view_switch_control | 生产函数，每次切换一个子资源，检查缓存判断是否增加开销 |
| image_mixed_read_write | 生产函数，固定种子的采样读取、计算写入、完整传输写入、视图/阶段变化 |
| image_full_range_control | 生产函数已有的完整范围快速路径，检查新增逻辑是否拖慢旧路径 |
| flat_upload_repeated | 真实 StreamBuffer::Copy 与 FlatDataMemo，重复的 512 字节只读参数上传 |
| flat_upload_mixed | 真实上传路径，重复参数与部分变化交替 |
| flat_upload_changing_control | 持续变化的数据，验证未命中冷却能限制缓存开销 |

另外用完整变化历史作参考，校验生产 RegistryChanges 的重叠、无关变化、过期与未来代次判定。
该项只报告正确性，不伪造昂贵的未命中工作来制造耗时收益。

图像测试分配实际 Vulkan 图像，必须有可用设备，已单独归类为 GPU 集成检查。
**测量的是 CPU 生成屏障和更新资源状态的耗时，不是 GPU 渲染时间；这些屏障没有作为场景提交执行。**
参数上传测试使用真实 Vulkan 映射缓冲区，校验源数据和返回偏移中的字节；另有 GPU 传输回读测试覆盖可见性。
只缓存不超过 2048 字节的只读 FlatUserData，字节相同且提交 tick/回绕代次一致才复用；
一般 guest 缓冲、GPU 写入资源和曝光纹理不走这个快捷路径。连续未命中会冷却 64 次，之后可重新探测稳定数据。
F11 新增 flat_data_memo_hits、flat_data_bytes_saved；BB_FLAT_DATA_MEMO=0 可停用该项以作对照。
纹理模型不包含 Rasterizer::BindResources 的完整纹理/缓冲绑定和未命中处理，
因此查表变慢或命中增加都不能独立推导整个绑定阶段的变化。

F11 不保存资源身份、访问顺序、视图或完整内容。当前负载的这些属性为显式合成假设，
不把计数校准称为游戏回放。绑定操作序列采集、完整 Vulkan 场景回放、资源加载、
游戏线程调度、曝光/画面一致性仍不在本版覆盖范围内。

## 测量与正确性

每个场景先校验结果，然后预热基线和候选版本，在同一个进程中交替执行 9 轮配对测量。
构造工作量、重置状态、分配主要容器和输出报告位于计时区间外。
固定种子保证可重复；性能统计保持开启，与 F11 测试相同。

图像路径逐操作比较屏障所有字段（仅忽略不同设备对象的图像句柄），并比较最后布局、
访问/阶段及每个子资源状态。重复轮次还比较语义校验和；写后读必须保留必要屏障。
基线是同一生产函数显式禁用只读记忆，候选启用。哈希基线恢复旧的最低位强制为 1 的规则。

报告包括每轮耗时、中位数、轮次 p95、MAD 波动、配对耗时比、命中和子资源检查次数。
轮次 p95 不是游戏逐帧 p95；不输出“预测 FPS”。
只有波动不超过 10%、时间足够长、配对结果持续改善时才标记组件收益；
退化、没有明确变化、噪声过大分别保留，不能将正确性通过冒充性能提升。
跨版本比较还检查硬件、负载范围和语义校验和；不同条件明确拒绝比较。

## 输出与空间

- `out/performance-sim/latest.md`：阅读报告。
- `latest.json`、`previous.json`：当前与上一轮结构化结果，最多保留两轮。
- `native.log`：最近一轮程序日志，最多 2 MiB。
- `gpu-user`：独立测试用现有引擎初始化目录，不接触游戏正式存档或全局配置。

本次测试可执行文件约 18 MiB，源码和报告很小；没有复制游戏文件或额外备份游戏可执行文件。
构建对象使用已有 out/gpu。持续执行会覆盖固定报告，不按轮次无限积累文件。

正确性回归入口为 `test.bat --gpu`，包括短版 CPU 和真实 Vulkan 图像校验。
性能时间不作为普通 CTest 的硬断言，避免后台负载导致随机测试失败；阶段收益用 `--require-gain` 独立检查。

## 本轮实测与修复

2026-10-07，现有 CLANG64 构建通过。`out/performance-sim-tests.log` 记录
156 项 Python、独立原生检查、24 项 CTest 单元和 9 项真实 Vulkan 集成检查全部通过。
无失败/跳过；历史 Linux/AppImage 模块按项目平台范围排除。

完整模拟运行 6 个场景、各 9 轮、20 万次操作，`--require-gain` 返回 0。
GPU 环境识别为 NVIDIA GeForce RTX 4090 Laptop GPU；测量对象仍是上述 CPU 组件。
重复部分只读中位耗时为 67.707 → 1.848 ms；混合读写为 126.833 → 75.655 ms。
这两个数分别比较本次函数禁用/启用只读记忆，不能换算成游戏帧率。

模拟检出频繁切换单个子资源时的额外记忆判定开销。已限制只读记忆仅用于至少八个子资源的范围，
并使不适用范围在条件判断中先退出。跨版本候选耗时由 2.288 → 1.993 ms，下降约 13%；
修复后候选与禁用记忆基线之间无明确退化，所有状态/屏障结果一致。

纹理压力模型命中由 7,125 增至 32,628，但单独查表计时为 1.112 → 1.476 ms，
仍报告疑似退化。没有完整未命中成本与实际访问序列，暂不据此认定整个纹理绑定变慢或回退生产哈希修复。
后续要评估该路径的真实收益，需要绑定操作采集/回放；当前程序尚未实现这部分。
