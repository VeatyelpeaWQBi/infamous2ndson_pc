# inFAMOUS：运行引擎集中着色器缓存

## 实现位置和流程

逻辑位于 Windows 运行引擎；不修改 `all_shaders.xpps`、`eboot.bin` 或游戏目录。
启动器将实际游戏目录的 `art/cache/all_shaders.xpps` 作为只读来源传给引擎。

1. 引擎校验 KCAP 标识并计算原始包内容指纹。
2. 从引擎自己的 `all_shaders.vkpack` 恢复 SPIR-V、特化信息、管线键和编译器配置。
3. 先创建 Vulkan 驱动缓存，再预热已记录的着色器特化、计算及图形管线。
4. 游戏提交着色器时，仍检查真实资源表和绘制状态；已知特化复用缓存，新特化走正常 PS4 → SPIR-V 转译。
5. 新结果进入后台写入队列，后台线程每五秒提交完整缓存；正常关闭先排空队列，再提交剩余数据。

这不是把原始包的全部字节直接当成 Vulkan 管线，也不替换游戏读取到的 PS4 数据。
首次遇到的新特化仍可能阻塞编译；尚未实现任意场景预测或全部未知管线的异步编译。
启动预热可能增加启动等待时间，目的是减少游玩中的重复编译。

## 文件和失效规则

默认位置：`profiles/CUSA00309/gpu/cache/CUSA00309/`。

- `all_shaders.vkpack`：单文件上限 64 MiB，包含逐项内容校验和、来源指纹和格式版本。
- `driver.vkc`：单文件上限 32 MiB，检查显卡厂商、型号、驱动版本、Vulkan UUID 和内容校验和。
- `.pending`：提交过程的临时完整副本；完成后原子替换正式文件。提交期间两个缓存的临时副本最多另外占用 96 MiB。

首次启用会导入现有散装缓存，保留旧文件。包来源改变或包损坏时重新积累，
不会从旧散装文件重新引入过期数据；编译器配置或着色器格式不匹配时重建相关缓存。
显卡驱动缓存不匹配时创建空缓存，不将不兼容内容交给驱动。
异常退出可能丢失最近一次后台提交之后的缓存增量；不能保证强制结束时执行析构保存。

启动日志包含 `Runtime Vulkan bundle`、`Vulkan driver cache loaded`、
`Preloaded ... shader specializations` 和 `Preloaded ... pipelines`，用于核实实际启用状态。
进程环境变量 `BB_SHADER_BUNDLE=0` 可回到散装缓存；`BB_PIPELINE_CACHE=0` 可禁用持久管线缓存。
无需修改系统环境变量。

## 本轮同时修复的运行问题

- 补齐日志明确缺失的 `sceSaveDataDialogGetResult`，按 PS4 ABI 返回对话框结果并保留调用方输出指针。
  无界面的覆盖确认默认取消；存档列表选择界面尚未实现，不能据此宣称所有存档流程已兼容。
- 修正缓存特化对象指向临时程序信息的悬空指针，拒绝冲突的特化索引。
- 截断或异常长度的缓存反序列化改为拒绝并跳过，避免因此终止启动。
- 纹理集合缓存扩展到没有有效后台准备结果的绘制路径；仍验证资源表、资源代次、清洁状态及必要屏障。
- 移除仅凭寄存器校验和复用图形管线的捷径：资源表可以在寄存器不变时被游戏改写。

存档对话框 ABI 参考：[shadPS4 保存对话框定义](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/save_data/dialog/savedatadialog_ui.h)。

使用现有 MSYS2 CLANG64 和 Windows Python；不新增或下载依赖。
