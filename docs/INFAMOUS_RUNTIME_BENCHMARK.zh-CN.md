# 实际游戏帧率基准

本程序启动真实 CUSA00309 游戏进程，自动载入固定存档并运行静止/镜头旋转两段负载。
它测量新游戏帧实际调用呈现后的主机时间间隔，输出 FPS、1% low、p50/p95/p99、最大帧时间和卡顿计数。
`performance-test.bat` 仍是组件微基准，不能代替本程序。

## 执行

```bat
rem 只检查输入、已有程序和预计空间，不复制数据、不启动游戏
runtime-benchmark.bat plan

rem 明确允许创建隔离测试存档、缓存和诊断，上限 512 MiB
runtime-benchmark.bat prepare --allow-test-data

rem 实际启动游戏，预热 45 秒，分别测量两个场景各 20 秒
runtime-benchmark.bat run --allow-test-data

rem 与上一版本比较相同固定存档和负载
runtime-benchmark.bat run --allow-test-data --compare out\runtime-benchmark\latest.json

rem 停用参数上传复用，测量真实游戏基线
runtime-benchmark.bat run --allow-test-data --flat-data-memo 0
```

需要已完成 `build.bat --build-tests` 和现有游戏准备流程。
程序不下载依赖，不复制游戏目录，不自动构建；直接使用现有 boot-linked.bin、content.bin、patches.bin 和 bb-probe.exe。
不要同时运行其他游戏或高负载任务，实际游戏窗口需要可见，不应最小化或打开游戏设置菜单。

## 隔离与记录

输出根目录固定为 `out/runtime-benchmark`，由 owner.json 标记所有权。
第一次创建 `seed/user` 和 `seed/gpu`；每轮从固定 seed/user 恢复到独立 user，正式存档只读。
独立 gpu 从种子缓存初始化后复用，避免每次重复冷编译；配置也从现有项目配置复制到独立文件。
测试前后检查正式存档指纹，运行报告记录固定存档、游戏和可执行文件指纹。
游戏只接受本轮脚本输入，实体手柄/键盘游戏操作不会混入负载。

控制命令只由配置了 BB_BENCH_CONTROL 的测试子进程处理，并按编号回执。
测试停止仅向自己启动的游戏请求关闭；不枚举、终止或重启用户的其他游戏进程。
失败时保留现场诊断，不能把崩溃、缺帧或没有场景数据当作测试通过。

保存 `latest.json/latest.md` 与上一份报告，诊断保存 run/debug 和 previous-run/debug。
相对于正式游戏测试，新增 `present-frames.csv`（含一份轮换备份），仅记录新游戏帧呈现，
原有 frames.csv 和 F11 CSV 继续保留提交、绑定、上传和等待信息。
开始/停止命令的回执给出测量时间边界；预热、加载及截图等待在测量区间之外。

## 验收范围

本版是实际游戏自动化基准，尚未实现完全脱离游戏进程的图形帧包回放。
存档和输入相同能重复负载，但游戏世界、加载与线程调度仍有波动，应多轮比较。
初次运行必须查看自动截图确认进入目标场景。未确认 scene_verified 时不能把菜单或错误页面当作游玩验收。

报告使用完整帧间隔，不根据 CPU 函数耗时推算 FPS；缺口、丢帧、尺寸变化和覆盖不足会使数据无效。
stable_50 / stable_60 基于整个有效测量段的最大帧间隔，分别允许 20.5 / 17.2 ms 的小幅主机调度容差。
它们是帧时间标准，不是平均 FPS 达标便通过。
主机呈现时间不等于显示面板扫描时间，程序不能仅凭它证明完全无撕裂或图像正确；同步呈现模式和场景截图需一起检查。

自动化执行约需 15 秒菜单等待＋45 秒预热＋两个 20 秒测量及截图/退出等待。
首次输入准备时明确预计空间并授权；当前存档约 0.32 MiB、缓存约 116.44 MiB，
种子与工作缓存约 234 MiB，另有有界诊断。无 --allow-test-data 时拒绝复制或实际运行。

## 首轮实测（2026-10-08）

已自动运行一次真实游戏并正常退出。截图确认是工厂屋顶人物操作场景，第二段镜头确实旋转；
两段均为 1920×1080、预热 45 秒、测量各 20 秒，记录无序号缺口或丢帧。

| 场景 | 平均 FPS | 1% low FPS | p95 帧时间 | 超过 50 ms 的帧 |
|---|---:|---:|---:|---:|
| 静止镜头 | 48.18 | 17.52 | 33.96 ms | 1 |
| 旋转镜头 | 47.71 | 23.45 | 33.96 ms | 3 |

本轮证明测试组件能测到实际游玩帧率，尚未达到稳定 50 或 60 FPS。
它也不是优化前后收益对比；旧测试使用的 3651×2054 尺寸与本轮不同，不能直接比较。
正式存档的测试前后指纹相同。完整数据在 `out/runtime-benchmark/latest.json` 与本轮诊断目录中。
本次回归：165 项 Python 测试、26 项原生单元测试、10 项真实 Vulkan 集成测试全部通过，失败及跳过均为 0。
回归日志在 `out/runtime-benchmark-tests.log`；隔离数据共 271.34 MiB，在授权的 512 MiB 内。
