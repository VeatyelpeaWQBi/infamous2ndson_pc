## 已得到实测支持的原因及改动

使用固定隔离存档，真实运行 CUSA00309；1920×1080、45 秒预热，静止和旋转镜头各测量 20 秒。
FPS 来自新游戏帧的主机呈现时间线，原始游戏和正式存档不修改。
所有测量仍需结合场景截图及退出状态判定；函数微基准不作为游戏 FPS 的替代。

1. **CPU 页状态检查**：大量只读资源绑定反复扫描 1024 页的位图。增加保守的脏字索引，
   干净区间可跳过扫描；设置脏页、上传清除和保护状态变化均维护索引。
   同一程序开关对照，关闭时静止／旋转为 46.31／46.56 FPS，开启时为 50.38／51.41 FPS。
   缓冲区绑定的每帧采集均值从约 6.33 ms 降到 3.37 ms。
2. **CPU 等待 GPU 回读**：游戏 CPU 的小写入会触发混合页面回读；原路径等待当前 GPU 提交全部完成。
   实测回读等待约 4 ms/帧，暖缓存测量阶段没有着色器编译。
   现在学习最多八个热点 4 KiB 页，在计算阶段提前复制并提交；CPU 只等待对应快照的时间点，
   无需等待后面无关绘制完成。首次实测平均等待降到约 0.50 ms/帧，约 1.04 次命中/帧。
3. **呈现节奏**：保持 Mailbox 同步模式，60 FPS 上限允许就绪帧在 guest vblank 之间呈现，
   减少原来约 16.7／33.3 ms 的量化。上限不会提高 CPU 处理能力。

快照最多占 32 KiB GPU 可回读缓存。重叠 GPU 写、CPU 上传、其他回读、未知地址着色器访问以及
解除映射会使旧快照失效；纹理别名页面不使用该捷径。仅复制当前 GPU 拥有的字节，保留 CPU 邻接数据。
缓存存储在旧提交完成前不得复用。失效和未命中仍执行原回读路径。

## 尚在处理的慢帧

镜头朝向建筑时，绘制量由约 3,000 次/帧增至约 7,600 次/帧，资源绑定均值达到约 11 ms。
这段没有着色器编译，仍主要受 CPU 图形前端工作量限制。
F11 分项含嵌套及跨线程活动，不能直接相加；Windows 命令线程 CPU 时间有 15.625 ms 台阶，
单帧解释需结合呈现时间线和分组均值。

进一步实验没有获得净收益，已移除小型只读缓冲区内容缓存、额外 GPU 脏字索引、精确 CPU 小写入代码。
小缓冲区缓存虽每帧命中约 10,349 次，但同程序开启／关闭时，静止 53.12／56.48 FPS，
旋转 51.27／52.97 FPS；不能以命中数声称游戏收益。
纹理工作线程 57.85／53.11 FPS，性能核 CPU Sets 调度对照 52.36／48.04 FPS，均未作为默认优化。
CPU Sets 实验只作用于创建时间和程序路径经验证的隔离测试子进程；进程退出后设置结束。

最新回读诊断发现固定缓存只保留最早八页。新的热点页面反复出现 `pool_full=1`，
因此实现受 GPU 完成时间保护的最近访问替换策略；`BB_READBACK_LRU=0` 可恢复固定池做同程序对照。
同程序固定池／最近访问替换的静止为 52.75／50.75 FPS，旋转为 48.65／49.77 FPS，平均 FPS 尚无明确整体收益。
替换策略开启时，静止／旋转回读等待均值为约 0.286／0.838 ms；该机制改善热点更新能力，不能以此宣称稳定帧率。

干净驻留缓冲区复用同程序关闭／开启对照：静止 53.19／56.30 FPS，旋转 51.60／51.05 FPS。
静止场景每帧约 23,211 次命中，旋转收益尚未成立，因此保留为实验开关。

## 设置与测试

inFAMOUS 启动入口默认设置 `BB_READBACK_PREFETCH=1`、`BB_CPU_WORD_SUMMARY=1`、`BB_FPS_LIMIT=60`。
显式环境覆盖仍保留，便于同一程序开关对照；不修改系统环境变量。

```powershell
# 已有工具链；不下载依赖。
$env:CMAKE_BUILD_PARALLEL_LEVEL='2'
.\build.bat --build-tests
.\test.bat --gpu
.\runtime-benchmark.bat run --allow-test-data
```

新增行为验证覆盖脏字索引与位图的随机对照、GPU 故障列表溢出后不丢页、
真实 GPU 回读快照在后续受阻提交完成前可读，以及新写入后的字节一致性。
已移除实验的测试不再算入当前通过总数。
未完成的最新构建、回归或真实游戏测量不能以旧测试结果代替。

自动化控制文件曾因 Windows 读句柄未共享删除权限而替换失败；改用共享删除的只读句柄，并提供
有期限的写入重试。持久权限错误仍报告失败，不扩大权限、不重启别的游戏进程。

构建时曾发生 LLVM 22 ThinLTO 完整 DWARF 类型输出崩溃。
当前尝试保留函数和源码行信息、减少调试类型信息并限制链接并行度；运行时优化及游戏线程数不降低。
当前配置已完成构建和回归；仍观察到个别 LLVM 堆分配阶段崩溃，串行重试恢复。不能据此断言根因已修复。
构建采用临时输出成功后替换，失败不再删除已存在的启动程序。不把编译器崩溃称为沙箱权限问题。
