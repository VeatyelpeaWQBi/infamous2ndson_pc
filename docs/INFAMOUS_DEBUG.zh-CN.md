# 游戏测试诊断使用说明

## 你需要做什么

1. 双击项目根目录 `run-infamous.bat`，正常使用 Xbox 手柄或键盘测试。
2. 出现画面异常、操作异常时，在游戏窗口按 **F10**。默认只记录轻量时间标记和逐帧性能数据，不暂停游戏线程。
3. 需要记录一段性能时，在游戏窗口按 **F11** 开始，再按一次 **F11** 停止。录制结束后会异步生成 `performance-recording-N.csv`；录制期间不暂停游戏线程。
4. 游戏完全卡住、F10 无响应时，双击 **debug-control.bat**。它向当前采集进程请求快照，不启动第二个游戏。
5. 出错后告诉开发者症状、最后进行的操作和大致时间即可。文件已经保存在项目目录，崩溃后不会立即删除。

收到后左上方显示 `F10 received`，即使关闭 FPS 也会显示。
该提示表示按键已收到；以 `input.txt` 的 `# MARK` 和 `runtime.log` 的 `F10 performance mark saved`
判断轻量标记完成。深度线程快照、完整渲染帧捕获只通过 `debug-control.bat snapshot` 请求，
或启动前设置 `BB_F10_DEEP=1`；深度模式会明显干扰当前帧。
普通 F11 用于性能录制；Shift+F11 保留全屏切换。
窗口线程本身无响应时仍使用 `debug-control.bat`；未配置诊断会话时会在日志明确报告。

## 记录的位置与内容

`out/CUSA00309/game-test.log` 保留启动概要、诊断目录、关键异常和退出结果。
完整详细信息在 `out/CUSA00309/debug/session-日期时间-编号/`。
`out/CUSA00309/debug/active.json` 指向当前或最近一次会话。

| 文件 | 信息 |
|---|---|
| `manifest.json` | 游戏/程序指纹、PID、运行参数、必要诊断开关；不复制全部环境变量 |
| `runtime.log`、`.1` | 带 UTC 收集时间的详细日志，包含错误、寄存器和调用栈 |
| `startup.log` | 启动阶段的前约 240 KiB，防止长时间测试把初始化信息轮换掉 |
| `input.txt`、`input.previous.txt` | 自动记录按键边沿、摇杆、扳机、触摸数量及 `# MOTION` 体感数据；模拟值最多 20 Hz，无需 F9 |
| `metrics.jsonl`、`.1` | 每秒 CPU 时间、内存、句柄、呈现帧计数/估算 FPS、疑似停止呈现标记 |
| `frames.csv`、`.1` | 有界逐帧间隔，以及绘制、管线选择、编译、上传和同步等待累计计数 |
| `performance-summary.json` | 游戏退出后按 F10 标记分段的 p50/p95/p99 和慢帧统计 |
| `performance-recording-N.csv` | 一次 F11 开始/停止之间的逐帧性能数据；最多保留约 4.5 分钟，超出部分在文件头报告丢帧 |
| `gpu-recent.txt` | 最近 512 个已执行绘制/调度/渲染范围操作，包括绘制数、管线句柄和着色器哈希 |
| `gpu-heartbeat.json` | 最近成功呈现时间、帧总数、图形操作数及图像尺寸 |
| `last-frame.bmp` | 最后一张诊断游戏帧；默认每 10 秒覆盖，支持常见 RGBA/BGRA、最大 1920×1080 |
| `status.json` | 实时状态、最终退出码、异常摘要、采集错误 |

输入字段为：`tick_ms thread buttons lx ly rx ry l2 r2 touch_count`。
`tick_ms` 与指标/GPU 操作共用 Windows 启动后的单调时钟，便于关联发生顺序。
它是输入时间线；不直接等同于 F9 回放格式，也不保证确定性重现。
`# MOTION` 行附带体感是否生效、四元数、加速度和角速度。F9 新记录包含体感字段，兼容旧八列回放。

## 自动异常采集与边界

- Windows 致命异常会输出通用寄存器、16 个 XMM 寄存器、崩溃线程栈，并请求全线程快照。
  等待最多 1.5 秒；某些栈没有展开信息或线程退出时，快照可以是不完整的，日志会说明。
- GPU 断言停止会尽力写出最近操作。GPU 缓冲锁被其他线程占用时，故障时写出不会等待，之前的周期记录仍保留。
- 有过成功呈现后，连续 15 秒没有新帧会记录 **疑似停止呈现**，首次请求线程快照。
  加载、最小化等也可能导致这个标记；不会据此自动终止或重启游戏。
- 使用任务管理器强制终止等情况无法取得事后完整寄存器；已写出的日志、输入、指标和画面仍保留。
- 这是本地诊断记录，不生成整个游戏进程的内存转储。GPU 占用率、所有资源绑定及完整触摸轨迹不在当前采集范围；鼠标模拟的体感数据会记录。
- 日常 F10 和逐帧数字记录不暂停渲染线程；完整画面读取、线程快照和深度帧捕获有运行开销。高于 1080p 或不支持的图像格式会跳过 BMP，指标仍记录实际尺寸。

## 大小限制

每轮详细日志最多 8 MiB×2、输入 4 MiB×2、指标 1 MiB×2，
启动记录约 256 KiB、GPU 操作约数十 KiB，BMP 最多约 5.94 MiB。
单轮通常不到 33 MiB，默认保留最近三轮完成的记录，约 100 MiB；当前同时运行的会话单独保留。
下次启动会按同一规则回收采集器已经退出的遗留会话；仅处理诊断目录内带本采集器标记的文件夹。
这些限额不包括项目原有的构建/着色器缓存和游戏存档。

## 验证

构建入口：`build.bat --build-tests`。
测试入口：`test.bat --gpu`，日志 `out/infamous-debug-tests.log`。
用例包括日志轮换/Unicode 上限、会话保留/路径保护、单个合成进程监控、不重启子程序、
合成崩溃的寄存器/全线程快照、虚拟手柄自动记录，以及多线程 GPU 操作环和非阻塞故障写出。
最终结果：120 项 Python/原生、2 项独立原生、14 项 CTest 单元/着色器/诊断检查、
4 项实际 Vulkan 集成测试全部通过；无失败、错误或跳过。

运行时指标通过现有 Windows API 获取：[GetProcessMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo)。
未安装调试器、服务或其他依赖，未修改全局 PATH、注册表或环境变量。
