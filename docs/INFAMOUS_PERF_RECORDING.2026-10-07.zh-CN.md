## 判断

这段录制最支持的瓶颈是 **GPU 命令线程的 CPU 前端处理，尤其是绘制资源绑定和高绘制量场景**。
一次 83 ms 尖峰还叠加了管线编译。Host Copy 和 Recorder 等待没有表现出同等规模的增长。

当前数据没有真实 GPU 执行时间，因此不能宣称 GPU 瓶颈已完全排除；但现有证据不支持优先降低显示分辨率，也不支持把问题归因于存档或磁盘读取。

## 下一步优化顺序

1. 先优化 `BindResources` 的重复 descriptor、纹理/缓冲范围查询和缓存失效路径，并用同一条路线比较慢帧数量。
2. 针对序号 918 一类尖峰，确认运行时管线缓存是否可以提前准备，避免游玩中首次编译。
3. 在资源绑定优化后，重新评估 DrawPipe 的安全并行恢复；不能直接打开当前被禁用的并行路径。
4. 如果优化后仍有慢帧，再补充真实 GPU 时间戳，区分 GPU 执行和 CPU 提交等待。

本报告只分析用户这次 F11 录制，没有重新启动游戏，也没有修改渲染逻辑。
